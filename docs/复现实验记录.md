## 6. MiniMax M3 与 Easy Dataset 真实模型链路（历史记录）

> 本节记录的是此前使用 Pro 的已完成实验，保留原样以保证证据可追溯。自 2026-08-14 起，平台运行配置统一使用 `MiniMax-M3`，不再调度 Pro。

网关从本机登录环境继承 `MINIMAX_API_KEY`，不把密钥写入命令、项目文件、数据库、日志或 Easy Dataset。运行参数为：

```text
LLM_MODEL=MiniMax-M3
LLM_JUDGE_MODEL=MiniMax-M3
LLM_CREDENTIAL_ROTATED=true
```

设置页最小请求结果：

```json
{
  "ok": true,
  "code": "verified",
  "message": "文本模型 MiniMax-M3 最小请求成功"
}
```

Easy Dataset 真实文档问答任务：

```text
任务 ID：32a1b0ca-52bb-4cc6-a207-f71ce280a67b
目标数量：1
模型：MiniMax-M3
耗时：约 27.9 秒
结果：succeeded
```

实际完成“检查服务、导入并分块、生成数据、整理结果”四个阶段，生成 1 条中文问题、答案和 CoT。统一 JSONL 导出返回：

```text
HTTP 200
X-Sample-Count: 1
X-Parse-Validated: true
```

真实调试过程中保留了两次失败证据：

1. `/split` 返回的展示对象不包含数据库 `chunkId`，适配器错误请求 `/chunks/None/questions`。
2. 修复 ID 后，传给上游的模型引用缺少本机代理 `endpoint`，上游返回 `Invalid URL`。

当前适配器会在分块后查询持久化 chunk，并传入带本机代理地址和占位 token 的完整模型对象。真实 MiniMax Key 仍只存在于网关进程环境。

Synthetic 早期完整工作流的 `llm_credential_not_ready` 记录仍作为门禁证据保留，但尚未使用当前模型配置重新执行。
