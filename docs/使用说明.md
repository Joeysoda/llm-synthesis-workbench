# 高质量数据平台使用说明

## 数据流程、医疗领域包与数据资产

除五个独立工具页面外，当前版本增加三项平台能力：

1. **数据流程**：打开 `/pipelines`，从文档问答、CoT 筛选、分类清洗或医疗模板开始。保存时会检查循环依赖、缺少输出节点和数据类型不兼容。通用模板用于编排与血缘登记，实际工具任务仍从各自工具页启动；医疗模板已可端到端运行。
2. **医疗高保真数据**：首次运行执行 `./scripts/docker-build.sh medical`，日常使用执行 `./scripts/docker-up.sh medical`。打开 `/medical`，新建医疗项目并使用默认 50 人参数。系统只调用 Synthea 生成完全虚构的记录，随后导出 FHIR、CSV、时间线、带资源证据的任务样本、质量报告与数据卡。
3. **数据资产**：打开 `/datasets` 查看不可覆盖的数据集版本。质量未通过的版本会保留问题报告但不能发布；通过后可发布，并保留工具版本、质量结果和血缘。

医疗包不接收真实病例，不代表任何真实医疗机构或中国人群分布，也不能用于诊断或治疗决策。

## 1. 启动与连接检查

```bash
cd integrated-system
./scripts/setup.sh
./scripts/dev.sh
```

浏览器打开 `http://127.0.0.1:5173`。进入“设置”后依次检查：

1. Gateway 显示 `127.0.0.1:18000` 且可达。
2. Easy Dataset 显示 `127.0.0.1:1717` 且可达。
3. Synthetic CLI、SynLogic 仓库和 Cleanlab 显示可用。
4. KAQG worker、Neo4j 和 Mosquitto 显示可用。
5. 文本模型在注入新密钥后点击“测试连接”，状态变为“已验证”。

网页不接收密钥，也不能提交任意本机路径。所有文件都必须先上传成当前工具项目中的资产。

## 2. 项目如何使用

每个工具页顶部都有项目选择器。项目相当于该工具的独立工作空间：

- 可以新建、切换、重命名和归档。
- 同名项目可以分别存在于不同工具中。
- Synthetic 项目不能运行 Easy Dataset 任务。
- 切换工具或项目后，页面只显示对应项目的文件、任务和样本。
- 刷新页面后会恢复该工具最后打开的项目和最近结果。

建议按材料或用途建项目，例如：

```text
Synthetic：产品文档 CoT
Easy Dataset：产品功能问答
SynLogic：5×5 Arrow Maze
KAQG：运维规范试题
Cleanlab：工单标签检查
```

## 3. Synthetic Data Kit

页面提供五种模式：

| 模式 | 输入 | 典型输出 |
|---|---|---|
| 普通 QA | 文档 | question + answer |
| CoT 思维链 | 文档 | question + answer + reasoning |
| 文档摘要 | 文档 | 文档摘要样本 |
| 补充 CoT | JSON / JSONL 对话 | 原对话 + reasoning |
| 多模态 QA | 图文材料 | 图片相关问答 |

### 3.1 CoT 示例

1. 新建项目“产品文档 CoT”。
2. 上传一份脱敏 DOCX、PDF、TXT 或 Markdown。
3. 选择“CoT 思维链”，数量填写 `30`。
4. 高级设置保持：分块 `4000`、重叠 `200`、筛选阈值 `7.0`。
5. 在参数预检中确认后开始生成。

平台内部自动执行：

```text
检查环境 → 解析输入 → 生成数据 → 质量筛选 → 整理结果
```

对应上游链路是：

```text
system-check → ingest → create --type cot → curate → save-as
```

任务完成后可以直接在当前页修改问题、答案和思维链，确认或驳回样本，并导出 JSONL、Alpaca、OpenAI FT、ChatML 或 Hugging Face 格式。

### 3.2 多文件与无模型解析

多文件直接在同一个上传区勾选，平台会为该任务建立隔离的批处理目录。真实文档解析不需要模型密钥；完整生成需要文本模型通过设置页的最小请求验证。

多模态模式需要独立视觉配置。未配置时参数可查看，但按钮明确禁用。

## 4. Easy Dataset

Easy Dataset 页面内有四个功能切换项。

### 4.1 文档问答

1. 上传 PDF、DOCX、TXT、Markdown 或 EPUB。
2. 选择文件后点击“导入并预览文本块”。
3. 检查分块内容，再选择单轮、多轮或两者都生成。
4. 如需扩大文体与受众差异，打开“GA 文体—受众扩增”。
5. 设置目标数量并开始生成。

示例输出：

```json
{
  "question": "该平台如何补充长尾样本？",
  "answer": "通过规则与模型生成稀缺场景数据，并进入质量筛选流程。",
  "reasoning": "答案来自输入材料中关于异常和长尾样本补充的段落。",
  "source": {
    "file": "高质量数据集产品功能介绍.docx",
    "chunk_id": "..."
  }
}
```

TXT 与 DOCX 会由网关转换为 UTF-8 Markdown，PDF 原样交给 sidecar。真实模型密钥只存在网关进程，Easy Dataset 保存的是本机代理地址和无敏感性的占位 token。

### 4.2 数据蒸馏

输入领域主题，例如“高质量安全数据集”，设置：

```text
标签层级：2
每层标签数：3
每标签问题数：3
```

页面先显示预计量。上述参数的叶子问题预计量为 `3² × 3 = 27`，便于在启动前避免指数级任务。运行后页面展示标签树、实际样本和导出入口。

### 4.3 图片问答

支持图片、PDF 和 ZIP。平台把文件交给 Easy Dataset 的图片导入 API，再由视觉模型生成问题和答案。第一版已经具备：

- 图片/PDF/ZIP 上传与资产隔离
- PDF 转图片和 ZIP 导入 sidecar 调用
- 视觉模型本机代理
- 每图问题数、语言和模型参数
- 统一样本与导出转换

没有 `VISION_BASE_URL / VISION_API_KEY / VISION_MODEL` 时不会发送请求，也不会生成假结果。视觉密钥提供后仍需完成一次真实端到端验收。

### 4.4 评估数据

选择文档后勾选判断题、单选题、多选题、简答题或开放题，设置每类数量并开始生成。生成结果仍在当前页筛选、编辑和导出，不需要跳转到全局审核或导出中心。

## 5. SynLogic Arrow Maze

推荐演示参数：

```text
数量：20
尺寸：5 × 5
预填箭头比例：0.3～0.9
最大尝试次数：100
```

点击生成后，页面直接显示题目网格和答案网格，可使用“上一题 / 下一题 / 随机抽样”浏览。

验证示例：

1. 保持标准答案，点击“用原始验证器校验”，应通过。
2. 点击“破坏第一个格子”或手动把一个方向改为非法值。
3. 再次校验，`ArrowMazeVerifier` 必须拒绝。

压力验收可把数量改为 `1000`。结果可导出为上游原始 JSONL或平台统一 JSONL。

## 6. KAQG

KAQG 页面用于把一份中文 PDF 转成知识图谱，并根据抽取事实生成单选题。

1. 上传带文本层的 PDF。扫描图片 PDF 会被拒绝。
2. 填写知识领域名称。
3. 分别设置低、中、高难度题数；首次测试建议各 `3` 题。
4. 确认后执行：

```text
检查环境 → 解析 PDF → 构建知识图谱 → 生成试题 → 评估试题 → 整理结果
```

完成后应看到节点数、关系数、章节、抽取事实以及每题的四个选项、唯一答案、目标难度、评估分数和来源证据。页面可下载：

- `kaqg-graph.json`：图谱节点和关系。
- `kaqg-questions.jsonl`：结构化题目。
- `kaqg-run-record.json`：输入、模型、版本、耗时和统计。

直接测试文件位于 `demo-inputs/kaqg/`。其中 PDF 用于上传，Markdown、标准事实和人工答案册用于人工核对。

## 7. Cleanlab

Cleanlab 默认不调用模型 API。上传模式要求数据量为 20～5000 条、至少两个标签、每个标签至少两条；首次可使用：

```text
demo-inputs/cleanlab/数据质量工单.csv
ID 列：id
文本列：text
标签列：label
```

平台使用字符级 TF-IDF、本机逻辑回归的样本外交叉验证概率、TruncatedSVD 与 Cleanlab 2.9.0。结果中的标签质量分数、异常分数和近重复组只是审核依据，不会自动改标签。

每条可执行三种决定：

- 接受建议：当前标签改为建议标签。
- 保留原标签：当前标签恢复为原标签。
- 手动修改：保存人工填写标签。

无论选择哪一种，原标签都保留在样本来源和审计报告中。CSV/JSONL 是清洗结果；`cleanlab-audit.jsonl` 保存全部分数和决策依据。

“导入已完成任务”适合检查其他工具结果的异常与近重复。QA、CoT 和题目通常没有分类标签，此模式不会宣称检测了错标签。

## 8. 已完成任务

默认只显示成功且有产物的任务。可按工具、项目、功能类型和时间筛选。

打开“需要处理”后可查看失败任务。详情使用普通阶段行：

```text
检查环境：失败
解析输入：待处理
生成数据：待处理
```

这里没有竖向 Timeline，也不会在首页突出失败数量。旧版混合项目以“历史实验”只读保留。

## 9. 导出与审核

工具页面中可以直接编辑样本，并设置：

- 待审核
- 已确认
- 已驳回

支持的统一导出格式包括 JSON、JSONL、CSV、Alpaca、OpenAI FT、ChatML 和 Hugging Face。返回文件前会重新解析内容；成功响应包含：

```text
X-Sample-Count: <数量>
X-Parse-Validated: true
```

## 10. 常见连接错误

| 状态 | 含义与处理 |
|---|---|
| 未配置密钥 | 当前进程没有 `MINIMAX_API_KEY` |
| 密钥尚未轮换确认 | 有密钥，但没有设置 `LLM_CREDENTIAL_ROTATED=true` |
| 401 密钥无效 | 新密钥被模型端点拒绝 |
| 余额或限流 | 模型账户额度不足或请求过快 |
| 模型名称不存在 | 检查当前供应商实际可用模型名 |
| 网络不可达 | 检查代理、DNS 与模型端点 |
| Easy Dataset 服务不可达 | 检查 `127.0.0.1:1717/api/projects` |
| KAQG 服务不可达 | 使用 Docker 启动，并检查 Gateway 返回的 KAQG、Neo4j、MQTT 状态 |
| PDF 无文本层 | 更换可复制文字的 PDF；扫描件需要先 OCR |
| Cleanlab 输入无效 | 检查数量、列名、标签数量、ID 唯一性和概率文件是否完整 |
| CLI 或仓库缺失 | 重新运行 `scripts/setup.sh` |
| 端点可用但生成失败 | 查看该任务的阶段、普通日志和产物校验结果 |

模型密钥不要填写到聊天、网页或配置文件中。
